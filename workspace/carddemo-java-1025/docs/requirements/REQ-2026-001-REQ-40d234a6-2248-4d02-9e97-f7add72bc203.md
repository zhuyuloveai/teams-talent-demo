## 1. 背景与目标（原文 §1）

### 1.1 业务背景

持卡人希望把单笔已入账消费或当期账单中的可分期金额分摊到后续月份以降低当期还款压力。现系统只有全额还款，缺少分期产品。本期在白金卡/金卡试点 3/6/12 期分期，沉淀分期计划、还款计划与提前结清能力。

### 1.2 目标（沿用原文量化指标）

| 目标 | 指标 |
|------|------|
| 提升分期渗透率 | 白金卡/金卡客户分期渗透率 8% → 15%（上线后 90 天） |
| 增加中间业务收入 | 分期手续费收入月增 12%（对比上线前 3 个月均值） |
| 缩短申请路径 | 申请到建计划耗时 < 3 秒（p95，本地 Compose 基准） |

> 说明：以上为原文模拟指标，未经验证，交付时不得据此声称业务效果已达成。

### 1.3 术语（沿用原文 §1.3）

单笔消费分期、账单分期、手续费率（月费率按剩余本金逐期计收：3 期 0.60%／6 期 0.55%／12 期 0.50%）、尾差（末期吸收）、去重键（`idempotencyKey`）、提前结清。术语使用遵循 `bank-domain-payments`：金额类术语统一「本金/手续费/违约金/减免」，不使用「划账」「转帐」等别名。

## 8. 数据需求（原文 §8）

### 8.1 数据字典

`installment_plan`（新增）：`plan_id` varchar(32) PK、`account_id` varchar(20) 非空索引、`customer_id` varchar(20) 非空、`source_type` varchar(16) `TRANSACTION`/`BILL`、`source_id` varchar(32) 非空、`principal` numeric(12,2) > 0、`term_months` smallint(3/6/12)、`monthly_fee_rate` numeric(6,4)、`total_fee` numeric(12,2) ≥ 0、`remaining_principal` numeric(12,2) ≥ 0、`status` varchar(16) `ACTIVE`/`SETTLED`/`CANCELLED`、`created_at` timestamptz、`settled_at` timestamptz 可空、`idempotency_key` varchar(64) 唯一索引、`version` int 默认 0（乐观锁）。

`installment_schedule`（新增）：`schedule_id` varchar(32) PK、`plan_id` varchar(32) FK、`installment_no` smallint（与 `plan_id` 联合唯一）、`due_date` date、`principal_due`/`fee_due`/`total_due` numeric(12,2) ≥ 0、`status` varchar(16) `PENDING`/`PAID`、`paid_at` timestamptz 可空。

视图 `account_limit_view` 扩展：`installment_occupied` numeric(12,2) ≥ 0 = 生效计划剩余本金合计。

数据一致性约束（v2 口径补充）：本金分摊合计 = `principal`；`principal_due` + `fee_due` 合计 = 还款计划 `total_due` 合计；`remaining_principal` 归零与额度释放必须同源、只发生一次（BR-INS-10）。

### 8.2 数据安全（原文 §8.2）

脱敏：响应与日志卡号仅后 4 位，客户姓名「姓 + \*」，JSON 落库前过滤敏感字段。传输 HTTPS、数据库连接 TLS，本期不新增需落地加密字段。留存：分期计划与还款计划 5 年、审计事件 3 年、去重键随计划同期留存（模拟制度，见 R-08）。访问：客户仅可读本人数据（越权 404），运营/风控只读，写操作限客服协助场景并审计。导出：需 `installment:read:any`，文件 24 小时有效且导出留痕。

## 14. 领域约束（按 `bank-domain-payments` L3）

- 业务规则编号：BR-INS-01..08（原文，编号不变）+ BR-INS-09..14（标注 v2 来源）。
- 监管/制度引用（模拟，沿用原文 §13）：《商业银行信用卡业务监督管理办法》关于分期业务信息披露与费率明示；行内分期业务管理办法（模拟编号 `INST-POLICY-2026`）。本文件为演示材料，不构成合规结论。
- 状态机：`ACTIVE` → `SETTLED`（结清）／`ACTIVE` → `CANCELLED`；还款计划行 `PENDING` → `PAID`。禁止绕过状态机直接改状态字段（需乐观锁 `version` 与状态前置校验）。
- 限额与额度：单账户 20 笔（v2 测试参数），额度占用按剩余本金独立分类，涉及余额变更必须经 account-service，会计影响必须过账 ledger 能力。
- 术语一致性：本稿使用「本金/手续费/违约金/减免/剩余本金」，未使用禁用别名；`term_check.py` 因脚本不在节点输入中而未执行。
