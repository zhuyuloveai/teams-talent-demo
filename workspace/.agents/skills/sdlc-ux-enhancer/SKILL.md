# SDLC 用户体验增强

## 角色定义

SDLC 用户体验增强工具，由 orchestrator 或 project-manager 调用，提供：
1. **进度看板**：可视化 G1-G8 进度，红色/黄色/绿色一目了然
2. **门禁旁路**：支持"带病放行"，自动记录旁路理由和审批链
3. **Agent 推荐引擎**：根据需求描述推荐应调用的 Agent 和 Skill
4. **一键全流程**：`@orchestrator 跑全流程` 即可，自动编排
5. **差异感知**：Agent 只处理变更部分，不影响未变更模块
6. **移动端通知**：门禁通过/失败时推送通知

### 2. 门禁旁路
当门禁未通过但业务确认可继续时：
- 记录旁路理由（必填）
- 记录审批人（必填）
- 记录已知风险和缓解措施
- 自动生成旁路记录，纳入审计证据

### 3. Agent 推荐引擎
用户描述需求后，自动匹配：
- 需要哪些 Agent 参与
- 各 Agent 应调用哪些 Skill
- 建议的执行顺序
- 预计的产出文件

### 4. 一键全流程
```
@orchestrator 跑全流程
需求：日累计限额参数化与超额预警
工程：EPS-demo-project/
```
orchestrator 自动：读取需求→规划阶段→并行调度→门禁校验→汇总报告

### 5. 差异感知
- 扫描代码变更，只处理受影响的模块
- 生成变更影响范围图
- 未变更模块自动跳过（标记为"无需变更"）

### 6. 移动端通知
- 门禁通过/失败时推送通知
- 支持企业微信/钉钉/Slack Webhook
- 通知内容包含：阶段、状态、关键指标、下一步行动

## 档位切换规则

| 档位 | 触发条件 | 附加动作 |
|------|---------|---------|
| L1 | 基础使用 | 进度看板+门禁旁路 |
| L2 | 推荐场景 | +Agent推荐+差异感知 |
| L3 | 管理场景 | +多项目看板+通知集成+SLA监控 |

## 深度档位（L3 实施级）

L3 实施级在 L2 基础上增加以下深度要求（管理场景/多项目/通知集成）：

### L3 工作流补充

- 多项目看板：同时展示多个项目的 G1-G8 进度与健康度
- 通知集成：企业微信/钉钉/Slack 多渠道推送，含 SLA 超时告警
- 旁路审计：旁路记录纳入审计证据链，支持按变更单追溯

### L3 质量门禁

- [ ] 看板状态与实际一致率 100%
- [ ] 旁路记录完整率 100%（理由/审批人/风险/缓解齐全）
- [ ] Agent 推荐命中率  90%

## 质量门禁

| 门禁 | 阈值 | 校验方式 |
|------|------|---------|
| 看板状态一致 | 100% | board_validate.py |
| 旁路记录完整 | 100% | bypass_validate.py |
| 推荐命中率 | ≥90% | recommend_validate.py |

## 失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 看板状态滞后 | 显示与实际不一致 | 定时刷新+手动刷新 | 强制重新读取 |
| 旁路滥用 | 所有门禁都旁路 | 旁路次数限制≤2/流程 | 超限拒绝+升级 |
| 推荐不准 | 推荐的Agent不匹配 | 积累案例库+持续优化 | 人工选择+反馈记录 |

## 升级路径

| 升级 | L1→L2增量 | L2→L3增量 | 回退条件 |
|------|----------|----------|---------|
| 看板 | +差异感知 | +多项目视图 | 单项目退回L2 |
| 旁路 | +风险提示 | +SLA超时告警 | 无旁路需求退回L1 |
| 推荐 | +案例匹配 | +ML推荐模型 | 案例不足退回L2 |
