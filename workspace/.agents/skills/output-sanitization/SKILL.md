# output-sanitization 技能

## 概述

本技能用于防止 Agent 产出中的敏感信息泄露：扫描、脱敏与阻断高危输出。银行场景涉及大量客户隐私、账户密钥与生产数据，任何产出在提交评审或对外输出前，必须经过脱敏扫描，确保不泄露 PII、密钥与生产数据片段。

**核心价值：**
- **敏感信息自动识别**：覆盖手机号/身份证/银行卡号/邮箱/密钥/IP/生产数据片段等银行常见敏感类型，多模式匹配降低漏检
- **脱敏不可逆**：掩码/替换/删除三类处置，脱敏后无法还原原始值，格式保持合理（如手机号保留前3后4）
- **高危阻断**：密钥类与生产数据片段命中即阻断提交（exit=2），防止密钥与生产数据进入评审/对外渠道
- **白名单防误脱敏**：L3 场景支持白名单规则，对测试数据/示例值/文档占位符免脱敏，降低误脱敏率

## 工作流

### Step 1: 加载敏感信息模式

根据任务场景加载敏感模式清单：

| 资料 | 内容 | 何时加载 |
|------|------|---------|
| `templates/sensitive-data-patterns.md` | 敏感模式清单（类型/正则/处置/阻断等级） | 任何脱敏任务 |
| `references/data-classification.md` | 数据分类分级（公开/内部/敏感/机密/绝密） | 判断处置等级时 |
| 外部白名单（可选） | 测试数据/示例值/文档占位符免脱敏清单 | L3 场景或误脱敏高发时 |

> 内置模式覆盖手机号/身份证/密钥三类（`sanitize.py`）与手机号/身份证/银行卡号/邮箱四类（`pii_scanner.py`）。扩展模式见 `templates/sensitive-data-patterns.md`。

### Step 2: 扫描产出文本

运行 `scripts/pii_scanner.py <目标文件> --json` 做 PII 识别，再运行 `scripts/sanitize.py <目标文件> --json` 做脱敏扫描：

- `pii_scanner.py`：识别 PII 类型与数量，退出码 1=有 PII，0=无 PII
- `sanitize.py`：扫描并就地脱敏，输出脱敏后文本与命中报告

```bash
# PII 识别（统计不脱敏）
python skills/output-sanitization/scripts/pii_scanner.py 产出文档.md --json

# 脱敏扫描（就地脱敏 + 报告）
python skills/output-sanitization/scripts/sanitize.py 产出文档.md --output 脱敏后.md --json
```

### Step 3: 敏感信息类型识别

识别命中项的类型，按处置等级分类：

| 类型 | 模式示例 | 处置等级 | 默认处置 |
|------|---------|---------|---------|
| 手机号 | `1[3-9]\d{9}` | 高敏感 | 掩码（前3+****+后4） |
| 身份证 | `\d{17}[\dXx]` | 高敏感 | 掩码（前6+********+后4） |
| 银行卡号 | `\d{16,19}` | 高敏感 | 掩码（前4+****+后4） |
| 邮箱 | `[\w.\-]+@[\w\-]+\.[\w.]+` | 中敏感 | 掩码（用户名首字符+***@域名） |
| 密钥 | `AKIA[0-9A-Z]{16}` / `sk-[A-Za-z0-9]{20,}` | 极敏感 | 替换为 `***REDACTED***` + 阻断 |
| IP 地址 | `\d{1,3}(\.\d{1,3}){3}` | 中敏感 | 掩码（前2段+.*.*） |
| 生产数据片段 | 生产库标记/脱敏标记缺失的数据库导出 | 极敏感 | 删除 + 阻断 |

> 完整模式清单见 `templates/sensitive-data-patterns.md`；数据分级见 `references/data-classification.md`。

### Step 4: 应用脱敏规则

按类型应用脱敏规则，脱敏不可逆：

1. **掩码**：保留部分字符，其余替换为 `*`（如手机号 `138****5678`）
2. **替换**：整段替换为占位符（如密钥 `***REDACTED***`）
3. **删除**：整段移除（如生产数据片段）

> 脱敏后须验证：格式合理（保留可识别结构）、不可逆（无法从掩码还原原值）、可用（脱敏后文档仍可阅读）。

### Step 5: 高危阻断判断

若命中密钥类或生产数据片段，`sanitize.py` 返回 `blocked=true` 且退出码=2，**直接阻断提交**：

- 阻断后须人工核查命中项是否为真实密钥/生产数据
- 若为真实密钥：从产出中删除，追溯密钥来源并轮换
- 若为测试/示例值：登记白名单后重跑（L3 场景）
- 阻断未解除前，产出不得进入评审或对外输出

### Step 6: 生成脱敏报告

按 `templates/sanitization-report.md` 模板生成脱敏报告，包含：

- 命中统计（类型/数量/处置方式）
- 阻断记录（高危命中的类型/位置/处置）
- 结论（通过 / 阻断）
- L3 必填深度字段（PII 命中详情/白名单命中/误脱敏标记/脱敏不可逆验证）

## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 内部扫描对齐、非正式检查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，常规产出提交与对外输出 | 安全确认 + 提交人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更的产出脱敏 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更的产出脱敏时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3 脱敏覆盖 PII/密钥/生产数据三类全覆盖，命中密钥与生产数据即阻断高危
- **白名单管理**：维护测试数据/示例值/文档占位符白名单，白名单内项免脱敏，降低误脱敏率
- **误脱敏统计**：记录白名单命中数与误脱敏标记，按月复盘误脱敏案例并优化模式
- **阻断审计日志**：每次阻断记录命中类型/位置/处置/操作人/时间，纳入安全审计
- **规则持续更新机制**：按月评审敏感模式清单，新增类型（如新密钥格式）及时入库
- **脱敏不可逆验证**：对掩码类脱敏做还原测试，确认无法从掩码值还原原值

### L3 质量门禁

- [ ] PII 召回 ≥ 95%（`pii_scanner.py` 命中数 / 人工标注 PII 数）
- [ ] 密钥 100% 阻断（`sanitize.py` 命中密钥时 `blocked=true` 且 exit=2）
- [ ] 脱敏不可逆验证通过（掩码值无法还原原值）
- [ ] 白名单命中率统计（L3 场景须记录白名单命中数与误脱敏标记）
- [ ] 阻断审计日志已记录（高危阻断含类型/位置/处置/操作人/时间）
- [ ] 规则持续更新机制已建立（月度评审敏感模式清单）

> 主模板含【L3必填】深度字段：`templates/sanitization-report.md`；详细档位定义见《Skill深度分级规范》。

## 脚本

| 脚本 | 用途 | 退出码 |
|------|------|--------|
| `scripts/sanitize.py` | 敏感信息扫描与脱敏（手机号/身份证/密钥，密钥命中即阻断） | 0/2/3 |

> 脚本详细接口、参数、退出码、检查项见 `scripts/README.md`。

### 脚本使用示例

```bash
# PII 识别（统计不脱敏，退出码 1=有PII，0=无PII）
python skills/output-sanitization/scripts/pii_scanner.py 产出文档.md --json

# 脱敏扫描（就地脱敏 + 报告，退出码 2=阻断，0=通过）
python skills/output-sanitization/scripts/sanitize.py 产出文档.md --output 脱敏后.md --json

# 仅扫描不写输出文件（报告输出到 stdout）
python skills/output-sanitization/scripts/sanitize.py 产出文档.md --json
```

`pii_scanner.py` 输出 JSON：
```json
{
  "pii_found": {"手机号": 2, "身份证": 0, "银行卡号": 1, "邮箱": 1},
  "total": 4
}
```

`sanitize.py` 输出 JSON：
```json
{
  "hits": {"手机号": 1, "身份证": 0, "密钥": 1},
  "blocked": true
}
```

> 当前脚本不支持白名单参数与外部模式整合（L3 期望能力）；L3 场景的白名单与误脱敏处置由 Agent 在报告层维护，脚本仅做确定性扫描。详见 `scripts/README.md` 的"能力边界与 L3 期望"。

## 常见失败模式与规避

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 误脱敏 | 测试数据/示例值被脱敏，影响文档可读性 | 上下文判断 + 白名单（L3）；测试数据用明显占位符（如 `138****0000`） | 登记白名单后重跑扫描 |
| 漏检 PII | 真实手机号/身份证未命中，泄露到产出 | 多模式匹配 + 规则持续更新；月度评审敏感模式清单 | 补充模式后重跑，人工复核漏检项 |
| 密钥未阻断 | 真实密钥进入评审/对外渠道 | `sanitize.py` 命中密钥即 `blocked=true` 且 exit=2；CI 门禁拦截 exit=2 | 删除密钥并轮换，重跑至 exit=0 |
| 脱敏可逆 | 掩码值可被暴力还原（如短手机号） | 掩码字符数 ≥ 原值 50%；密钥类用替换而非掩码 | 改为替换处置后重跑 |
| 白名单滥用 | 白名单过宽导致真实敏感信息免脱敏 | 白名单须安全确认 + 定期评审；白名单项须标注免脱敏理由 | 收敛白名单后重跑 |
| 生产数据片段漏判 | 数据库导出/日志片段未识别为生产数据 | 生产数据标记 + 脱敏标记缺失检测；L3 覆盖生产数据片段 | 补充生产数据模式后重跑 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式产出提交/对外输出 | 全部【L2必填】章节（敏感模式清单/脱敏报告/命中统计） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线/高风险变更 | PII/密钥/生产数据三类全覆盖、白名单规则、误脱敏统计、阻断审计日志 | 风险降级或场景简化，经安全确认可回 L2 |

**人工兜底点**：L3 的白名单规则与误脱敏处置须由安全与合规共同确认；Agent 起草，安全确认后定稿。降级须经安全审批并记录原因。
