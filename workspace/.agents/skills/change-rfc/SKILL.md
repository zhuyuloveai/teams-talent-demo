# change-rfc 技能

## 概述

本技能用于生成合规、完整、可评审的变更申请单。

## 工作流

1. 汇总变更内容（类型/原因/范围）
2. 填充RFC字段（影响/窗口/回滚/干系人）
3. 附加证据链接（影响分析/测试退出/发布计划）
4. 运行字段校验（rfc_validate.py）
5. 提交审批


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | RFC字段探讨、变更思路对齐、Demo走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，发布包就绪后申请生产变更 | 变更经理审核 + CAB评审 |
| L3 实施级 | 高风险变更/监管报送/跨系统集成/首次上线/紧急变更RFC | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、紧急变更（紧急通道上线）、影响客户数 > 1万时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3 RFC含完整字段+证据链接+窗口冲突检查
- 紧急变更补审计划
- RFC字段须含变更分级（低/中/高）与分级依据，分级依据引用风险评估产出
- 证据链接须指向可访问的工单/报告（影响分析、测试退出报告、发布计划、回滚演练记录），非占位文本
- 窗口冲突检查须引用 window_scheduler.py 输出，冲突项标注处置方案
- 紧急变更RFC须标注紧急通道、紧急理由、事后补审时限（≤ 24 小时）与补审责任人
- 回滚方案字段须含回滚步骤数、回退时长上限、演练通过证据链接

### L3 质量门禁

- [ ] rfc_validate.py 退出码 0（十项必填字段齐全：RFC编号/变更类型/变更原因/变更范围/影响分析/测试退出/发布计划/回滚方案/建议窗口/干系人）
- [ ] 变更分级字段（低/中/高）与分级依据齐全，依据引用风险评估产出
- [ ] 证据链接指向可访问工单/报告（非占位文本，非"待补充"）
- [ ] 窗口冲突检查引用 window_scheduler.py 输出，冲突项有处置方案
- [ ] 回滚方案含回滚步骤数、回退时长上限、演练通过证据链接
- [ ] 紧急变更RFC标注紧急通道、紧急理由、补审时限（≤ 24h）与补审责任人
- [ ] RFC字段与影响分析/测试退出报告/发布计划交叉一致（无矛盾）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 字段缺失 | rfc_validate.py 报 missing 项 | 校验脚本拦截 + 模板必填字段 | 补齐缺失字段后重跑脚本，退出码=0 才提交 |
| 证据链接占位 | 链接为"待补充"/"#" | 禁止占位文本，链接须指向可访问工单 | 替换为有效工单链接后重提交 |
| 变更分级缺失 | RFC无变更分级或无分级依据 | 模板强制分级字段 + 引用风险评估 | 引用风险评估产出后重提交 |
| 窗口冲突未检查 | RFC建议窗口未引用 window_scheduler.py | RFC字段强制引用窗口冲突报告 | 引用冲突报告并标注处置方案后重提交 |
| 回滚方案空洞 | 仅写"回退到上一版本"，无步骤数/时长上限 | 回滚方案字段量化（步骤数/时长上限/演练证据） | 补全回滚量化字段后重提交 |
| 紧急变更未补审 | 紧急RFC上线后超 24 小时未补审 | 紧急通道流程门禁（T+24h 告警） | 24 小时内完成补审并记录紧急理由 |
| 字段交叉矛盾 | RFC影响范围与影响分析报告不一致 | RFC与影响分析/测试退出/发布计划交叉校验 | 修正矛盾字段后重提交 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 发布包就绪，申请生产变更 | 全部【L2必填】章节（十项字段/证据链接/窗口冲突检查/审批提交） | CAB退回，降为草稿 |
| L2 → L3 | 高风险/监管/跨系统/首次上线/紧急变更 | 变更分级与依据、证据可访问性、窗口冲突处置方案、回滚量化字段、紧急通道补审记录 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的变更分级与紧急通道补审须由变更经理与风险条线负责人共同确认；Agent 起草RFC，变更经理确认后定稿。降级须经 PM + 合规审批并记录原因。
