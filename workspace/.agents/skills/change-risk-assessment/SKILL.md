# change-risk-assessment 技能

## 概述

本技能用于对变更进行分级并给出风险与应急结论。

## 工作流

1. 读取RFC与影响分析/测试证据
2. 判定变更等级（低/中/高）
3. 评估影响面与失败概率
4. 核对回滚与应急预案
5. 输出风险评估表


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 变更风险初评、思路对齐、Demo走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，RFC起草时常规变更风险评估 | 变更经理审核 + 风险条线负责人签字 |
| L3 实施级 | 高风险变更/监管报送/跨系统集成/首次上线/紧急变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、影响客户数 > 1万、跨系统依赖 ≥ 3 个时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3风险评估量化（影响面/概率/回滚完整性）+等级判定依据
- 高风险变更应急计划完备
- 量化影响面（受影响系统数/接口数/客户数/交易笔数/数据条数）与失败概率（参考历史同类变更事故率）
- 回滚完整性证据化：回滚步骤演练通过、回退时长上限、数据回滚可行性（DDL/DML/配置三类）
- 等级判定须引用历史同类变更案例（≥ 3 个），并说明本次与历史案例的差异点
- 高风险变更须附独立应急计划：值班通讯录、二线/三线升级路径、业务连续性预案（BCP）、客户公告模板
- 风险分级建议须由 risk_classifier.py 输出，人工可调整但须记录调整理由

### L3 质量门禁

- [ ] 影响面量化（系统数/接口数/客户数/交易笔数/数据条数五项齐全）
- [ ] 失败概率引用历史同类变更事故率（≥ 3 个案例）
- [ ] 回滚完整性证据化（演练通过 + 回退时长上限 + DDL/DML/配置三类回滚方案）
- [ ] 等级判定与历史案例比对一致（差异点已说明）
- [ ] 高风险变更附应急计划（值班通讯录 + 升级路径 + BCP + 客户公告模板）
- [ ] risk_classifier.py 退出码 0 且 level 字段非空
- [ ] 评估结论与 RFC/影响分析/测试退出报告交叉一致（无矛盾）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 等级低估 | risk_classifier.py 输出"高"但人工判为"中"且无理由 | 与历史同类变更案例比对（≥ 3 个） | 引用历史案例后重判，或记录调整理由并升级审批 |
| 影响面未量化 | 仅写"影响较大"，无系统数/客户数/交易笔数 | 模板强制五项量化字段 | 补全量化数据后重提交 |
| 失败概率主观 | 无历史事故率引用，凭经验拍数 | 引用变更管理平台事故率统计 | 补引用历史数据后重提交 |
| 回滚方案空洞 | 仅写"回退到上一版本"，无演练/时长上限 | 回滚演练记录 + 时长上限 + DDL/DML/配置分类 | 完成演练并附证据后重提交 |
| 证据引用缺失 | 风险评估未链接影响分析/测试退出报告 | 必填校验 + 模板字段 | 补链接后重提交 |
| 应急计划缺失 | 高风险变更无值班通讯录/BCP | L3强制应急计划章节 | 补全应急计划后重提交 |
| 等级与RFC矛盾 | 风险等级为"高"但RFC建议窗口为业务高峰 | 与 RFC/窗口排期交叉校验 | 调整窗口或重新评估等级后重提交 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入RFC正式起草 | 全部【L2必填】章节（等级判定/影响面/失败概率/回滚核对/证据引用） | RFC退回，降为草稿 |
| L2 → L3 | 高风险/监管/跨系统/首次上线/紧急变更/影响客户数 > 1万 | 影响面五项量化、历史事故率引用、回滚完整性证据、应急计划、BCP、等级调整理由 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的等级判定与应急计划须由风险条线负责人与变更经理共同确认；Agent 起草评估表，风险条线负责人确认后定稿。降级须经 PM + 合规审批并记录原因。
