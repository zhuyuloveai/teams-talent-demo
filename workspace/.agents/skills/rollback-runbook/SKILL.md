# rollback-runbook 技能

## 概述

本技能用于定义发布失败时的快速、安全回滚路径。

## 工作流

1. 识别回退点（代码/数据/配置）
2. 编写回滚步骤（顺序/命令/校验）
3. 明确数据回滚与一致性处理
4. 定义验证方法与责任人、时限
5. 回滚演练


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 回滚思路对齐、回退点讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，发布计划编制时必配回滚手册 | 发布负责人 + 运维签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/重大变更 | ARB/CAB评审 + 深度门禁全通过 |

**自动升 L3 场景**：回滚涉及反洗钱、限额参数、客户资金、跨行接口、生产数据变更、数据库回滚、监管报送窗口、首次上线时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。


## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3回滚手册含命令级步骤+验证命令+数据一致处理+责任人/时限
- 回滚演练记录
- 回退点全覆盖：代码回退（制品版本）/数据回退（数据库快照+事务日志）/配置回退（上一版本配置），每类回退点有独立步骤
- 数据一致性处理：数据库回滚须含前向兼容检查（旧版本能否读新数据）、冲正交易处理、幂等性保障，DBA签字确认
- 回退触发条件量化：错误率>0.1%、P95>基线1.5倍、TPS<基线80%、资金类告警任一命中即触发回退
- 回退时限明确：从触发到完成≤15分钟（代码）/≤30分钟（含数据），超时升级至应急响应
- 回滚演练：上线前须在 UAT 环境完成全流程演练，演练记录含耗时/问题/改进项
- 回滚后验证：业务指标（交易成功率/金额核对）+技术指标（TPS/P95/错误率）全部恢复正常基线

### L3 质量门禁

- [ ] 回退点全覆盖（代码/数据/配置三类）
- [ ] 数据回滚含前向兼容检查与DBA签字
- [ ] 回退触发条件量化（错误率/TPS/P95/资金告警）
- [ ] 回退时限明确（代码≤15分钟/含数据≤30分钟）
- [ ] 上线前UAT演练完成且有记录（含耗时/问题/改进）
- [ ] 回滚后验证含业务+技术指标恢复基线
- [ ] rollback_check.py 退出码 0（回滚/步骤/验证/责任人/时限齐全）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 步骤不可执行 | 回滚步骤无具体命令，无法操作 | 强制命令级步骤+UAT演练 | 改写为命令级并演练后重审 |
| 数据回滚遗漏 | 仅回滚代码未回滚数据，导致数据不一致 | DBA确认项+前向兼容检查 | 补齐数据回滚步骤后重审 |
| 回退点不全 | 仅含代码回退，缺配置/数据回退 | 三类回退点全覆盖（代码/数据/配置） | 补齐缺失回退点后重审 |
| 触发条件模糊 | 仅写"异常则回退"，无量化指标 | 量化阈值（错误率/TPS/P95/资金告警） | 补齐量化阈值后重审 |
| 时限无定义 | 回退耗时无上限，影响业务 | 时限明确（代码≤15min/含数据≤30min） | 补齐时限并演练后重审 |
| 演练缺失 | 上线前未演练，回滚时才发现问题 | UAT全流程演练+记录 | 补演练后重审 |
| 回滚后无验证 | 回滚后未验证业务恢复 | 业务+技术指标恢复基线验证 | 补齐验证步骤后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式发布计划编制 | 全部【L2必填】章节（回退点/步骤/验证/责任人/时限） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/数据库回滚/首次上线 | 三类回退点+数据一致性(DBA签字)+量化触发条件+时限+UAT演练记录+回滚后验证 | 风险降级或变更简化，经CAB确认可回 L2 |

**人工兜底点**：L3 的数据回滚方案与前向兼容检查须由 DBA 与发布负责人共同确认；Agent 起草回滚手册，DBA与运维确认后定稿。降级须经 CAB + ARB 审批并记录原因。
