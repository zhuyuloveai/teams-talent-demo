# qa-unit-test-strategy 技能

## 概述

本技能用于制定单测策略并审核开发单测质量，确保UT作为质量第一道闸门有效。

## 工作流

1. 制定UT策略：覆盖率阈值（行/分支/MC/DC）、测试范围、关键路径清单
2. 确定单测框架与工具（JUnit/Jest/Pytest + Mock + 覆盖率）
3. 评审开发UT计划：范围与优先级
4. 审核UT用例设计：关键逻辑、边界、异常
5. 覆盖率报告审核（coverage_review.py）
6. 测试质量评估（ut_quality_score.py）
7. 未达标处理：识别缺口，要求补测，必要时阻断提测
8. 持续改进：UT指标趋势分析


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | UT策略思路探索、覆盖率阈值讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，开发自测前UT策略制定与覆盖率审核 | 测试评审会 + QA架构师签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、资金冲正/幂等逻辑、核心账务模块变更时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- 覆盖率双重门禁：总体覆盖率≥80%（可配置）+ 关键路径覆盖率100%，由 coverage_review.py 自动审核
- UT质量评分≥80分（独立性40%+断言充分性40%+命名规范20%），由 ut_quality_score.py 自动评分
- 关键路径清单须含资金类/账务类/权限类/报送类模块，每条路径有UT用例覆盖且覆盖率100%
- 未达标阻断提测规则：总体覆盖率<80% 或 关键路径有缺口 或 质量评分<80，任一不达标即阻断
- UT用例须覆盖边界值（min/min-1/max/max+1）与异常路径（空值/越权/超时/并发/幂等）
- 覆盖率缺口清单可识别：列出未覆盖的关键路径与缺口原因，指导补测优先级

### L3 质量门禁

- [ ] 总体覆盖率≥80%（coverage_review.py 退出码 0）
- [ ] 关键路径覆盖率100%（coverage_review.py 无 critical_gaps）
- [ ] UT质量评分≥80分（ut_quality_score.py 退出码 0）
- [ ] 关键路径清单含资金/账务/权限/报送类模块
- [ ] UT用例覆盖边界值与异常路径（空值/越权/超时/并发/幂等）
- [ ] 未达标有阻断提测记录与补测计划
- [ ] 覆盖率缺口清单可识别（缺口路径+原因+补测优先级）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 覆盖率虚高 | 总体覆盖率高但关键路径有缺口 | 关键路径覆盖率100%门禁（coverage_review.py） | 补测关键路径后重跑 coverage_review.py |
| 关键路径遗漏 | 资金/账务/权限模块未列入关键路径 | 关键路径清单强制四类模块（资金/账务/权限/报送） | 补充关键路径后重审 |
| UT质量评分低 | 断言不充分或命名不规范 | ut_quality_score.py 评分≥80门禁 | 改进断言与命名后重跑 ut_quality_score.py |
| 边界值未覆盖 | UT用例未写 min/min-1/max/max+1 | 边界值用例checklist强制四值 | 补充边界值用例后重审 |
| 异常路径未覆盖 | 缺空值/越权/超时/并发/幂等用例 | 异常路径用例checklist强制五类 | 补充异常路径用例后重审 |
| 未达标未阻断 | 覆盖率或评分不达标仍允许提测 | 未达标阻断提测规则（任一不达标即阻断） | 触发阻断后补测至达标再提测 |
| 缺口清单缺失 | 未列出未覆盖路径与缺口原因 | 缺口清单强制字段（路径+原因+补测优先级） | 补充缺口清单后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式UT审核 | 全部【L2必填】章节（覆盖率阈值/测试范围/关键路径清单/UT用例设计/覆盖率报告） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 覆盖率双重门禁、UT质量评分、关键路径四类模块、边界值与异常路径覆盖、阻断提测规则、缺口清单 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的关键路径清单与阻断提测决策须由 QA 架构师与开发负责人共同确认；Agent 起草，QA 架构师确认后定稿。降级须经 PM + 合规审批并记录原因。
