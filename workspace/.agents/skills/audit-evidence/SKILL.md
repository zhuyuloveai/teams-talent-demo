# audit-evidence 技能

## 概述

本技能用于保证 SDLC 全链路可追溯，输出可独立举证的审计证据包。覆盖"需求→故事→MR→测试→变更→发布→PIR"七环节，确保任一工件可向上溯源至业务诉求、向下追踪至生产运行结果。

**核心价值：**
- **全链路可追溯**：REQ→US→MR→TC→CHG→REL→PIR 七环节闭环，任一断链即告警
- **审计证据可举证**：每个工件附链接 + ID + 时间戳 + 责任人，独立成包，无需口头补证
- **缺失可解释**：缺失项必须标注原因（不适用/暂缺/替代证据）并经合规确认，杜绝"无声缺失"
- **监管可应对**：证据包格式对齐行内审计与监管检查要求，迎检时可按需求/变更单维度即时检索

## 工作流

### Step 1: 收集阶段工件

按 SDLC 七环节收集工件清单，每个工件须包含：环节 / ID / 工件链接 / 责任人 / 时间戳。

| 环节 | ID 前缀 | 工件类型 | 收集方式 |
|------|---------|---------|---------|
| 需求 | REQ | 需求说明书 | 从需求平台导出（含评审记录） |
| 故事 | US | 用户故事/迭代故事 | 从敏捷平台导出（含验收标准） |
| MR | MR | 合并请求/代码变更 | 从代码仓库 API 拉取（含评审/CI 结果） |
| 测试 | TC | 测试用例 + 执行报告 | 从测试平台导出（含通过率/缺陷） |
| 变更 | CHG | 变更单（RFC） | 从变更管理平台导出（含审批/回滚预案） |
| 发布 | REL | 发布单 + 发布记录 | 从发布平台导出（含灰度/回滚记录） |
| 复核 | PIR | 事后复盘报告 | 从 PIR 平台/Confluence 导出 |

子步骤：
1. 确认本次审计范围（单需求/单变更单/单个发布批次/全量盘点）
2. 按范围从各平台拉取工件清单（API 优先，人工补录次之）
3. 为每个工件标注 ID 与链接（URL 须直达工件详情页，不得仅指向列表）
4. 标注责任人（每环节至少一人，发布环节须含发布负责人 + 值班 SRE）
5. 标注时间戳（创建/评审/合并/执行，按环节语义取关键节点）

> 注意：CHG 与 RFC 的关系——本技能默认变更环节 ID 前缀为 `CHG`（Change），兼容历史 `RFC` 前缀；证据包中以 `CHG` 为准，`RFC-xxx` 须在证据包中映射为 `CHG-xxx` 并保留映射记录。

### Step 2: 校验 ID 链完整性

运行 `scripts/trace_check.py` 校验 ID 链：

- 每个环节的 `id` 字段非空
- ID 编码符合 `references/id-conventions.md` 规范（前缀 + 年份 + 序列号）
- 相邻环节 ID 可关联（如 `US-xxx` 的需求字段指向 `REQ-xxx`）
- 链完整率 = 100% - 缺失环节数 / 7

校验结果以 JSON 输出，含 `chain_complete`、`missing_ids`、`broken_links` 字段。

ID 链校验规则（详见 `references/id-conventions.md`）：

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| 前缀合法 | 必须为 REQ/US/MR/TC/CHG/REL/PIR 之一 | 标记缺失，须修正 |
| 年份一致 | 同一链路内年份须一致或递增（跨年项目除外） | 警告，须说明 |
| 序列号唯一 | 同前缀序列号全局唯一 | 标记重复，须修正 |
| 关联字段 | US→REQ / MR→US / TC→US / CHG→MR / REL→CHG / PIR→REL | 断链须记录原因 |

### Step 3: 检查证据链接有效性

对每个工件的 `url` 字段做可达性校验：

- URL 格式合法（http/https）
- URL 可达（可选，`--check-urls` 开启）
- URL 直达工件详情页（非列表页/首页）
- 链接有效率 = 可达链接数 / 总链接数

> 生产环境校验 URL 可达性可能触发审计告警，建议在审计窗口内执行，或仅校验格式与域名白名单。

链接失效处理：
1. 失效链接标记为 `broken`，记录失效原因（404/403/超时/平台迁移）
2. 失效链接须在证据包中附"替代证据"（如本地归档副本、平台导出快照）
3. 替代证据须经合规与阶段负责人共同确认

### Step 4: 生成审计证据包

按 `templates/evidence-pack.md` 模板生成证据包：

1. **主表**：七环节工件清单（环节 / ID / 工件链接 / 责任人 / 时间戳 / 状态）
2. **缺失项清单**：缺失环节 + 缺失原因 + 替代证据（L3 必填）
3. **全链路 ID 矩阵**（L3 必填）：REQ↔US↔MR↔TC↔CHG↔REL↔PIR 关联矩阵
4. **追溯索引**（L3 必填）：按需求 ID 与变更单 ID 双向索引
5. **合规确认**：合规与阶段负责人签字记录

证据包输出格式：
- Markdown（人类可读，用于评审与归档）
- JSON（机器可读，用于门禁自动化消费）

### Step 5: 输出追溯链报告

追溯链报告含：

- **链完整率**：X/7 环节齐全（百分比）
- **链接有效率**：X/7 链接有效（百分比）
- **缺失项统计**：按环节分布
- **缺失原因分类**：不适用 / 暂缺 / 替代证据 / 未提供
- **门禁结论**：PASS / WARNING / FAIL

门禁判定规则：
- 链完整率 < 100% 且缺失项无原因 → FAIL
- 链接有效率 < 100% 且无替代证据 → FAIL
- 链完整率 = 100% 且链接有效率 = 100% → PASS
- 其他 → WARNING（须人工确认）

### Step 6: 归档与版本化

1. 证据包归档至审计平台（含版本号、生成时间、生成人）
2. 历史证据包保留可追溯（不覆盖，仅追加版本）
3. 证据包哈希值上链或哈希存证（监管要求场景）
4. 归档后通知合规与审计条线

## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 内部追溯对齐、非正式检查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，常规门禁评审与发布 | 合规确认 + 发布负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更的审计 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更的审计追溯时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- **全链路 ID 矩阵**：输出 REQ↔US↔MR↔TC↔CHG↔REL↔PIR 的 N×N 关联矩阵，每个交叉单元格标注关联 ID 或"未关联"
- **缺失原因分类表**：每项缺失须分类（不适用 / 暂缺 / 替代证据 / 已丢失）并附说明
- **替代证据登记**：缺失工件须提供替代证据（归档副本 / 平台快照 / 人工说明），经合规确认
- **证据链接自动验证**：URL 可达性校验全量执行（`--check-urls`），失效链接 100% 有替代证据
- **按需求/变更单追溯索引**：支持按 `REQ-xxx` 或 `CHG-xxx` 双向检索全链路工件
- **缺失项影响评估**：每项缺失须评估对资金安全/监管报送/业务连续性的影响

### L3 质量门禁

- [ ] 链完整率 100%（7/7 环节齐全）
- [ ] 缺失项 100% 有原因（不适用/暂缺/替代证据/已丢失）
- [ ] 链接有效率 100%（或失效链接 100% 有替代证据）
- [ ] 全链路 ID 矩阵已输出且无"未关联"空格
- [ ] 按需求/变更单追溯索引可双向检索
- [ ] 缺失项影响评估已覆盖资金安全/监管报送/业务连续性
- [ ] 合规与阶段负责人共同签字确认

> 主模板含【L3必填】深度字段：`templates/evidence-pack.md`；详细档位定义见《Skill深度分级规范》。

## 脚本

| 脚本 | 用途 | 退出码 |
|------|------|--------|
| `scripts/trace_check.py` | 校验全链路 ID 链完整性与链接有效性 | 0/2/3 |

### 脚本使用示例

```bash
# 基本校验（仅校验 ID 链，不校验 URL 可达性）
python skills/audit-evidence/scripts/trace_check.py evidence.json

# 含 URL 可达性校验（生产环境慎用，可能触发审计告警）
python skills/audit-evidence/scripts/trace_check.py evidence.json --check-urls --json

# JSON 输出（供门禁自动化消费）
python skills/audit-evidence/scripts/trace_check.py evidence.json --json
```

输出 JSON 示例（完整链路）：
```json
{
  "total": 7,
  "missing_ids": [],
  "broken_links": [],
  "chain_complete": true
}
```

输出 JSON 示例（缺失 ID + 失效链接）：
```json
{
  "total": 7,
  "missing_ids": [
    {"stage": "变更", "id": ""}
  ],
  "broken_links": ["发布"],
  "chain_complete": false
}
```

> 脚本详细接口、参数、退出码与单测对应见 `scripts/README.md`。
>
> **能力边界说明**：当前 `trace_check.py` 仅校验 ID 非空与 URL 格式，**不输出缺失原因**。L3 要求的"缺失原因分类"与"替代证据登记"须在证据包 Markdown 中人工填写，脚本不参与判定。后续版本规划支持缺失原因字段。

## 常见失败模式与规避

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| ID 断链 | 某环节 ID 为空或不符合编码规范 | trace_check.py 自动检测缺失 ID 并拦截 | 补录 ID 后重跑校验 |
| 链接失效 | URL 404/403/超时，无法直达工件 | `--check-urls` 校验；失效链接附替代证据（归档副本/快照） | 提供替代证据并经合规确认后重试 |
| 缺失无声 | 某环节缺失但无原因说明 | 证据包模板强制缺失原因字段（L3 必填） | 补填原因 + 替代证据后重跑 |
| CHG/RFC 混用 | 变更环节 ID 前缀不统一 | 默认 CHG，RFC 须映射并保留映射记录 | 统一为 CHG 后重试 |
| 工件链接指向列表页 | URL 仅指向平台首页或列表，无法直达详情 | 校验 URL 路径含工件 ID | 替换为详情页 URL 后重试 |
| 责任人缺失 | 某环节无责任人或仅有团队名 | 证据包模板强制责任人字段（个人，非团队） | 补录个人责任人后重试 |
| 证据包不可独立举证 | 需口头说明才能理解 | 证据包自包含（ID + 链接 + 时间戳 + 责任人 + 状态） | 补全字段后重新生成证据包 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式门禁评审/发布 | 全部【L2必填】章节（工件清单/ID链/链接有效性/追溯链报告） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线/高风险变更 | 全链路ID矩阵、缺失原因详表、证据链接有效性验证、按需求/变更单追溯索引 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的缺失原因与替代证据须由合规与阶段负责人共同确认；Agent 起草，合规确认后定稿。降级须经合规审批并记录原因。
