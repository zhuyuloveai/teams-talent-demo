# sec-threat-model 技能

## 概述

本技能用于在设计阶段系统识别安全威胁并确定缓解措施。

## 工作流

1. 梳理数据流与信任边界
2. 按STRIDE逐维度分析（Spoofing/Tampering/Repudiation/Information Disclosure/DoS/Elevation）
3. 生成威胁清单（威胁/影响/可能性/缓解）
4. 标注残余风险
5. 输出威胁模型文档


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 威胁建模思路对齐、STRIDE 初步分析、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，设计定稿前威胁建模 | 安全工程师 + 设计负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/外部接口 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：设计涉及反洗钱、限额参数、客户资金、密码学实现、跨行接口、生产数据访问、监管报送字段时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。


## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3输出数据流图+STRIDE×资产矩阵+威胁-缓解映射
- 残余风险登记（责任人/接受理由）
- 每项威胁标注 CWE 编号与攻击路径（入口点→信任边界跨越→受影响资产→潜在影响）
- 高风险威胁（影响=高且可能性≥中）须有补偿控制清单（如WAF/限流/审计监控）并验证有效
- 威胁分级采用 DREAD 评分（Damage/Reproducibility/Exploitability/Affected Users/Discoverability），DREAM≥20 须强制缓解
- 残余风险须由责任人书面接受并登记到风险登记册，含接受理由与复评时限（≤6个月）
- 攻击面覆盖矩阵：认证/授权/数据/输入校验/日志/会话/密码学/接口 8 维度全覆盖，缺项须说明理由

### L3 质量门禁

- [ ] STRIDE 6 维度×资产矩阵全覆盖（无空行）
- [ ] 每项威胁有 CWE 映射与攻击路径说明
- [ ] 高风险威胁（DREAD≥20）有强制缓解措施
- [ ] 残余风险登记到风险登记册（含责任人/接受理由/复评时限≤6个月）
- [ ] 补偿控制清单已验证有效
- [ ] 攻击面 8 维度全覆盖（认证/授权/数据/输入/日志/会话/密码学/接口）
- [ ] 数据流图标明全部信任边界与数据流向

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 模板化空泛 | 威胁描述与具体设计脱节，无资产/无信任边界 | 强制数据流图+STRIDE×资产矩阵 | 补齐数据流与资产矩阵后重审 |
| 漏威胁 | STRIDE逐项有空行，认证/会话等维度未覆盖 | 清单式检查+8维度覆盖矩阵 | 补齐缺失维度后重审 |
| 缓解不可验证 | 缓解措施仅写"加强校验"，无具体控制 | 缓解须含具体控制（WAF规则/限流阈值/审计日志） | 改写为可验证控制后重审 |
| 残余风险无登记 | 高风险威胁接受后无记录，无复评 | 强制登记到风险登记册+复评时限≤6个月 | 补登记并设定复评后重审 |
| CWE映射缺失 | 威胁无CWE编号，无法关联知识库 | 强制CWE字段填写 | 补齐CWE后重审 |
| 攻击路径不清 | 未说明入口点与信任边界跨越 | 强制攻击路径字段（入口→边界→资产→影响） | 补齐攻击路径后重审 |
| 补偿控制未验证 | 豁免依赖的WAF/限流未验证有效性 | L3要求补偿控制有效性验证证据 | 补验证后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式设计评审 | 全部【L2必填】章节（数据流/STRIDE/威胁清单/残余风险） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/密码学/跨行接口 | CWE映射+攻击路径+DREAD评分+补偿控制+风险登记册+8维度覆盖矩阵 | 风险降级或场景简化，经ARB确认可回 L2 |

**人工兜底点**：L3 的残余风险接受与补偿控制有效性验证须由安全工程师与设计负责人共同确认；Agent 起草威胁模型，安全工程师确认后定稿。降级须经 ARB + 合规审批并记录原因。
