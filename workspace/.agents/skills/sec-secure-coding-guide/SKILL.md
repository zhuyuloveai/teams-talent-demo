# sec-secure-coding-guide 技能

## 概述

本技能用于从开发源头降低安全风险，提供可操作的安全编码规则。

## 工作流

1. 按语言/框架提供安全编码规则
2. 覆盖OWASP Top 10银行场景变体
3. 提供正反示例（正确写法vs漏洞写法）
4. 代码评审时自动检查安全编码合规性（secure_code_scan.py）
5. 定期更新以覆盖新的漏洞模式


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 安全编码咨询、规则草案讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，代码评审中自动检查安全编码合规 | 安全工程师签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/外部接口 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：代码涉及反洗钱、限额参数、客户资金、密码学实现、外部接口认证、生产数据访问、监管报送字段时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。


## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3输出OWASP Top10银行映射+正反示例+代码级检查
- 扫描规则与工具（SAST）联动
- 每条规则映射 CWE 编号与 OWASP Top 10 银行变体编号，并给出修复代码片段（正确写法）与漏洞代码片段（错误写法）
- 资金/密码学/认证类规则须含合规依据（如等保2.0/PCI DSS/银保监会要求）与违反后果说明
- secure_code_scan.py 规则集与 SAST 工具（SonarQube/Checkmarx）规则编号双向映射，避免规则漂移
- 误报项须登记到误报白名单并定期复核（每季度），白名单条目含误报理由与复核人
- 新增漏洞模式（如 CVE 公开后 7 天内）须补充对应规则与正反示例

### L3 质量门禁

- [ ] OWASP Top 10 银行变体全覆盖（10/10，每项有正反示例）
- [ ] 每条规则有 CWE 映射与合规依据
- [ ] secure_code_scan.py 退出码 0（无 fatal/critical 违规）
- [ ] 误报率<15%且白名单条目均有复核记录
- [ ] 资金/密码学/认证类规则含合规依据与后果说明
- [ ] SAST 规则编号双向映射无漂移
- [ ] 新增 CVE 7 天内补充规则与示例

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 规则太泛不实用 | 规则描述模糊，开发者无法据以修复 | 提供具体代码级正反示例 | 改写为可操作示例后重审 |
| 误报率高 | 大量正常代码被标记为违规 | 持续调优规则+误报白名单季度复核 | 调优规则并登记白名单后重跑 |
| OWASP覆盖不全 | 银行变体（如限额绕过）未覆盖 | L3要求10/10全覆盖并标注银行变体 | 补齐缺失变体后重审 |
| CWE映射缺失 | 规则无CWE编号，无法关联知识库 | 强制CWE字段填写 | 补齐CWE后重审 |
| SAST规则漂移 | secure_code_scan.py与SonarQube规则不一致 | 规则编号双向映射+定期对账 | 对账修正后重审 |
| 合规依据缺失 | 资金/密码学规则无等保/PCI依据 | 强制合规依据字段 | 补齐依据后重审 |
| 新漏洞响应慢 | 新CVE未及时补充规则 | CVE公开7天内补充规则 | 补充规则与示例后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式代码评审 | 全部【L2必填】章节（OWASP映射/正反示例/扫描规则） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/密码学/外部接口 | CWE映射+合规依据+SAST双向映射+误报白名单+CVE响应SLA | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的合规依据与 SAST 规则双向映射须由安全工程师与合规共同确认；Agent 起草规则与示例，安全工程师确认后定稿。降级须经 Sec负责人 + 合规审批并记录原因。
