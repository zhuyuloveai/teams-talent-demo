# dev-data-sql 技能

## 概述

本技能用于高质量的数据层开发，确保性能、安全、可维护。

## 工作流

1. 数据模型实现：建表SQL、字段、索引、约束、注释
2. 数据访问层：DAO/Repository/Mapper，参数化查询
3. 数据迁移脚本：增量DDL/DML + 回滚，版本化
4. ETL/数据加工：清洗、转换、装载，批量优化
5. SQL性能优化：执行计划、索引、避免全表扫描
6. 事务与一致性：事务边界、分布式事务、最终一致
7. 安全与权限：敏感字段加密、行级权限、审计日志
8. 数据验证：完整性校验、迁移回滚验证、ETL对账

## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 表结构草案、SQL 草稿、ETL 方案讨论 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，表结构设计、SQL 开发、数据迁移、ETL 脚本开发 | DBA 评审 + 技术负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及账户余额表、交易流水表、限额参数表、监管报送数据、生产数据迁移、跨库数据同步时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3输出建表SQL+索引设计+迁移（含回滚）+ETL
- SQL性能与安全自检（执行计划/参数化）
- 字段级校验：金额（精度/正负/币种）、账户号（格式/校验位）、流水号（唯一性/顺序）、时间（时区/格式）逐字段定义约束与校验规则
- 事务一致性：明确事务边界、隔离级别、分布式事务方案（Saga/TCC/最终一致），资金类操作须含补偿与冲正路径
- 幂等性：迁移与 ETL 操作定义幂等键（业务日期+批次号），重复执行安全（可重入），数据回滚验证（data_diff.py）
- 边界值：金额 min/max、字段长度上限、分页 size 上限、批次大小上限逐项构造用例
- 异常路径覆盖：迁移失败回滚、ETL 中断恢复、数据不一致对账、连接超时重试逐路径给出策略

### L3 质量门禁

- [ ] 无 SQL 注入风险（sql_lint.py 退出码 0，无 critical）
- [ ] 迁移可回滚（migration_verify.py 退出码 0，has_rollback=true）
- [ ] 数据一致性验证通过（data_diff.py 退出码 0，consistent=true）
- [ ] 关键查询走索引（执行计划验证，无全表扫描）
- [ ] 敏感字段加密（卡号/身份证/手机号/密码加密存储）
- [ ] 事务边界明确（资金类操作含补偿与冲正路径）
- [ ] 迁移与 ETL 幂等（重复执行安全，含回滚验证）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| SQL性能问题 | 全表扫描/无索引/P95 超阈值 | sql_lint.py + 执行计划分析 | 加索引或改写 SQL 后重跑 lint |
| 数据迁移失败 | 迁移中断/数据丢失/不可回滚 | 回滚演练+分批次+migration_verify.py | 回滚后分批重跑迁移 |
| N+1查询 | 循环内单条查询导致大量 DB 往返 | 代码审查+批量加载（IN/JOIN） | 改批量查询后重测性能 |
| SQL注入风险 | 字符串拼接 SQL | 参数化查询+sql_lint.py 拦截 | 改参数化后重跑 lint |
| 迁移无回滚脚本 | ALTER 后无法回退 | migration_verify.py 强制回滚段 | 补回滚脚本后重跑验证 |
| 数据不一致 | 迁移/ETL 后源目标数据不匹配 | data_diff.py 对账+分批校验 | 修复后重跑 data_diff |
| 敏感字段未加密 | 卡号/身份证明文存储 | 字段级加密+审计日志 | 加密后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式 SQL 开发/DBA 评审 | 建表 SQL、索引设计、迁移脚本（含回滚）、参数化查询 | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 字段级校验规则、事务边界与补偿路径、幂等键定义、敏感字段加密、数据一致性对账 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的字段级校验规则与事务边界须由 DBA 与后端架构师共同确认；Agent 起草，DBA 确认后定稿。降级须经 PM + 合规审批并记录原因。
