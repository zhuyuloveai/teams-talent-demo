# pm-status-reporting 技能

## 概述

本技能用于自动汇总项目数据生成标准化状态报告。

## 工作流

1. 自动采集进度/质量/风险/成本数据
2. 对比计划与实际，识别偏差
3. 按报告模板生成各章节内容
4. 标注异常项与需决策项
5. 生成可视化图表（进度曲线、燃尽图、风险热力图）


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 状态草拟、数据预汇总、Demo走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，周报/月报/里程碑报告 | PM审核 + 项目发起人签字 |
| L3 实施级 | 高风险项目/监管报送项目/里程碑门禁/首次上线状态报告 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、里程碑门禁临近（≤ 7 天）、偏差超阈值（进度偏差 > 10% 或成本偏差 > 5%）时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3报告数据自动采集+偏差根因+异常排名
- 含门禁状态与决策项
- 状态多源对齐：进度数据须从项目管理平台/代码仓库/测试平台/CI/CD 多源采集，并交叉校验一致（不一致项标注差异原因）
- 偏差根因分析：每条偏差须含根因（需求变更/资源不足/技术难题/外部依赖/供应商延迟五类之一）与纠正措施
- 里程碑门禁状态：报告须含 G1/G2/G3/G4 门禁通过状态，未通过门禁须附阻断原因与预计通过时间
- 异常项排名：异常项按影响度排序（高/中/低），每项含责任人、预计解决时间、升级路径
- 决策项明确：报告中须独立列出需决策的事项（决策人、决策截止时间、备选方案、推荐方案）

### L3 质量门禁

- [ ] status_aggregator.py 输出 `deviations` 字段，每条偏差含根因（五类之一）与纠正措施
- [ ] 状态数据多源采集（≥ 3 个来源：项目管理平台/代码仓库/测试平台/CI/CD），不一致项标注差异原因
- [ ] 里程碑门禁状态完整（G1/G2/G3/G4），未通过门禁附阻断原因与预计通过时间
- [ ] 异常项按影响度排序，每项含责任人、预计解决时间、升级路径
- [ ] 决策项独立列出（决策人、决策截止时间、备选方案、推荐方案）
- [ ] 数据一致率 100%（多源交叉校验通过）
- [ ] 报告含进度曲线、燃尽图、风险热力图三类可视化图表

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 数据来源不一致 | 多源数据偏差 > 5% 未标注 | 单一数据源 + 多源交叉校验 | 标注差异原因后重提交 |
| 偏差无根因 | 仅写"进度滞后"，无根因分类 | 强制根因五类（需求/资源/技术/外部/供应商） | 补全根因与纠正措施后重提交 |
| 门禁状态缺失 | 报告无 G1/G2/G3/G4 状态 | 模板强制门禁状态章节 | 补全门禁状态后重提交 |
| 异常项未排名 | 异常项无优先级、无责任人 | 异常项按影响度排序 + 责任人字段 | 补全排序与责任人后重提交 |
| 决策项模糊 | 决策项无决策人/截止时间/备选 | 决策项独立章节 + 四项字段 | 补全四项字段后重提交 |
| 可视化缺失 | 报告无进度曲线/燃尽图/风险热力图 | 模板强制三类图表 | 生成图表后重提交 |
| 偏差超阈值未升级 | 进度偏差 > 10% 或成本偏差 > 5% 未升级 | 自动升 L3 门禁 | 升级 L3 并经 ARB 评审后重提交 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式周报/月报/里程碑报告 | 全部【L2必填】章节（数据采集/偏差识别/报告模板/异常标注/可视化图表） | 评审退回，降为草稿 |
| L2 → L3 | 高风险项目/监管报送/里程碑门禁/首次上线/偏差超阈值 | 多源对齐、偏差根因五类、门禁状态、异常排名、决策项四项字段 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的偏差根因与决策项须由 PM 与项目发起人共同确认；Agent 起草状态报告，PM 确认后定稿。降级须经 PM + 合规审批并记录原因。
