# qa-test-case-design 技能

## 概述

本技能用于从需求与验收标准导出高质量、可追溯的测试用例集。

## 工作流

1. 读取需求与验收标准
2. 逐条导出正常/边界/异常用例
3. 补充回归用例
4. 关联RTM（需求↔故事↔用例）
5. 用例评审后入库


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 用例设计思路探索、设计方法讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，测试策略定稿后用例设计与评审入库 | 用例评审会 + QA负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、资金冲正/幂等场景时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- 用例覆盖正常/边界/异常/回归四类并关联RTM，边界值用例显式标注 min/min-1/max/max+1
- 每条用例含步骤/测试数据/预期结果，测试数据含构造方式与数据来源（脱敏生产数据/造数脚本/固定数据池）
- 异常路径用例独立编号：接口异常/超时/并发/幂等/降级/熔断/重试场景全覆盖
- 资金类用例须含幂等性与冲正场景（重复提交、网络抖动、部分成功的预期行为）
- 覆盖率矩阵：需求×用例类型（正常/边界/异常/回归）二维追溯，无空行空列
- 回归用例集标注基线版本与优先级（P0核心先行），回归范围与变更影响可追溯

### L3 质量门禁

- [ ] 需求覆盖率100%（RTM无孤儿需求）
- [ ] 边界值用例显式标注 min/min-1/max/max+1
- [ ] 异常路径用例独立编号（接口异常/超时/并发/幂等/降级/熔断）
- [ ] 资金类用例含幂等性与冲正场景
- [ ] 覆盖率矩阵无空行空列（需求×用例类型二维完整）
- [ ] 可执行率≥95%（步骤/数据/预期三要素齐全）
- [ ] 回归用例集标注基线版本与优先级

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 用例与需求脱节 | 用例未关联REQ编号或关联到不存在需求 | rtm_check.py 拦截未关联与孤儿需求 | 修正关联后重跑 rtm_check.py |
| 只有正常路径 | 缺边界值与异常路径用例 | L3强制四类用例（正常/边界/异常/回归） | 补充边界与异常用例后重审 |
| 边界值未显式标注 | 限额类用例未写 min/min-1/max/max+1 | 边界值用例模板强制标注四值 | 补充边界值标注后重审 |
| 异常路径遗漏 | 缺接口异常/超时/并发/幂等/降级场景 | 异常路径用例独立编号 + checklist | 补充异常路径用例后重审 |
| 测试数据无构造方式 | 用例数据未说明来源与构造脚本 | 测试数据字段强制含构造方式与来源 | 补充数据构造方式后重审 |
| 覆盖率矩阵有空行空列 | 需求×用例类型二维矩阵有遗漏 | 矩阵完整性校验（无空行空列） | 补充缺失用例后重审 |
| 回归用例无基线版本 | 回归用例未标注基线版本与优先级 | 回归用例模板强制基线版本字段 | 补充基线版本后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式用例评审 | 全部【L2必填】章节（正常/边界/异常用例/RTM关联/步骤数据预期） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 边界值四值标注、异常路径独立编号、幂等性冲正场景、覆盖率矩阵、回归基线版本 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的边界值用例与异常路径用例须由 QA 与业务负责人共同确认；Agent 起草，业务确认后定稿。降级须经 PM + 合规审批并记录原因。
