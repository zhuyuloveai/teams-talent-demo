# qa-system-test-design 技能

## 概述

本技能用于系统化设计系统测试用例，确保功能需求全覆盖。

## 工作流

1. 需求分析：逐条阅读需求与验收标准，识别测试点
2. 用例设计方法：等价类/边界值/决策表/状态迁移/场景法
3. 功能测试用例：正常+分支+配置差异
4. 边界测试用例：输入/数据/容量/时间边界
5. 异常测试用例：错误输入/异常状态/依赖故障/网络异常
6. UI/UX测试用例：布局/交互/提示/操作习惯
7. 数据验证用例：字段校验/一致性/规则计算
8. 需求追溯：每条用例关联需求ID（req_coverage_check.py）
9. 用例评审：交叉评审+业务评审


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | ST用例设计思路探索、设计方法讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，ST阶段用例设计与评审入库 | 用例评审会 + QA负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、资金冲正/幂等场景、核心账务系统用例设计时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- 输出场景矩阵（正常/边界/异常×接口/数据/并发/安全四维），矩阵无空行空列
- 用例方法标注（等价类/边界值/决策表/状态迁移/场景法），每条用例标注所用设计方法
- 边界值用例显式标注 min/min-1/max/max+1，异常用例覆盖错误输入/异常状态/依赖故障/网络异常/并发/幂等
- 需求覆盖率100%由 req_coverage_check.py 自动校验，无 missing 需求
- 用例去重由 testcase_dedup.py 自动检测，无重复用例（标题+步骤哈希）
- 资金类用例须含幂等性与冲正场景，限额类用例须含边界值与越权场景

### L3 质量门禁

- [ ] 需求覆盖率100%（req_coverage_check.py 退出码 0，无 missing）
- [ ] 场景矩阵四维覆盖（正常/边界/异常×接口/数据/并发/安全无空行空列）
- [ ] 用例方法标注齐全（等价类/边界值/决策表/状态迁移/场景法）
- [ ] 边界值用例显式标注 min/min-1/max/max+1
- [ ] 资金类用例含幂等性与冲正场景
- [ ] 用例无重复（testcase_dedup.py 退出码 0）
- [ ] 可执行率≥95%（步骤/数据/预期三要素齐全）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 用例粒度过粗 | 一条用例覆盖多个功能点无法独立执行 | 拆分子用例（一个用例一个验证点） | 拆分后重审 |
| 遗漏异常场景 | 缺错误输入/异常状态/依赖故障/网络异常场景 | 异常场景checklist + 场景矩阵四维覆盖 | 补充异常场景后重审 |
| 需求理解偏差 | 用例与需求语义不一致 | 业务评审环节 + req_coverage_check.py 校验 | 修正理解后重审 |
| 需求覆盖遗漏 | 部分REQ未被任何用例覆盖 | req_coverage_check.py 拦截 missing 需求 | 补充用例后重跑 req_coverage_check.py |
| 边界值未标注 | 限额类用例未写 min/min-1/max/max+1 | 边界值用例模板强制标注四值 | 补充边界值标注后重审 |
| 用例重复 | 多条用例标题与步骤完全相同 | testcase_dedup.py 检测重复（标题+步骤哈希） | 删除重复用例后重跑 testcase_dedup.py |
| 场景矩阵有空行空列 | 正常/边界/异常×接口/数据/并发/安全矩阵有遗漏 | 矩阵完整性校验（无空行空列） | 补充缺失场景后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式ST用例评审 | 全部【L2必填】章节（需求分析/用例设计方法/功能/边界/异常/UI/数据验证用例/需求追溯） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 场景矩阵四维覆盖、用例方法标注、边界值四值标注、幂等性冲正场景、用例去重 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的场景矩阵与资金类用例须由 QA 与业务负责人共同确认；Agent 起草，业务确认后定稿。降级须经 PM + 合规审批并记录原因。
