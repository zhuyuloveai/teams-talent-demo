# qa-test-execution 技能

## 概述

本技能用于管理测试执行进度并生成报告。

## 工作流

1. 制定测试执行计划（轮次/范围/资源/时间）
2. 分配用例并跟踪执行状态（test_progress_tracker.py）
3. 每日同步进度与阻塞项
4. 生成测试日报/周报
5. 测试完成后生成测试总结报告


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 执行计划思路探索、进度跟踪讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，测试执行阶段进度跟踪与日报生成 | 测试评审会 + QA负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、资金冲正/幂等场景执行时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- 执行记录含环境/版本/数据/结果四要素，每条执行记录可追溯至用例ID与构建版本号
- 日报含阻塞项与遗留缺陷分级（致命/严重/一般），阻塞项有责任人 + 预计解除时间
- 执行率与通过率每日由 test_progress_tracker.py 自动汇总，数据与测试管理系统一致（差异≤2%）
- 资金类用例执行失败须触发阻断机制：停止该批次执行，缺陷登记后由QA负责人评估是否继续
- 测试退出前完成遗留缺陷风险评估：致命/严重缺陷0、一般缺陷有处置计划、退出指标三达标
- 执行记录与缺陷双向可追溯（执行记录↔缺陷ID↔用例ID↔需求ID）

### L3 质量门禁

- [ ] 执行记录含环境/版本/数据/结果四要素
- [ ] 日报含阻塞项分级与责任人及预计解除时间
- [ ] 执行率与通过率每日由脚本汇总且与系统一致（差异≤2%）
- [ ] 资金类用例失败有阻断机制与QA负责人评估记录
- [ ] 测试退出指标三达标（执行率100%/通过率≥98%/遗留缺陷分级合规）
- [ ] 执行记录↔缺陷↔用例↔需求四向可追溯
- [ ] test_progress_tracker.py 退出码 0（数据采集无错误）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 进度数据滞后 | 日报数据与实际执行状态不一致 | test_progress_tracker.py 自动采集 + 差异≤2%门禁 | 重新采集数据后重生成日报 |
| 报告信息不全 | 日报缺阻塞项/缺陷分级/责任人 | 日报模板强制字段（阻塞项分级+责任人+预计解除时间） | 补充缺失字段后重审 |
| 执行记录无版本 | 执行记录缺构建版本号无法追溯 | 执行记录强制环境/版本/数据/结果四要素 | 补充版本号后重审 |
| 资金类失败未阻断 | 资金类用例失败后继续执行未暂停 | 资金类失败阻断机制 + QA负责人评估记录 | 暂停执行并登记缺陷后重审 |
| 退出指标未达标 | 致命/严重缺陷非0或通过率<98%仍退出 | 退出指标三达标门禁（执行率/通过率/遗留缺陷） | 修复缺陷后重测至达标 |
| 四向追溯断裂 | 执行记录无法关联到缺陷/用例/需求 | 执行记录↔缺陷↔用例↔需求四向追溯矩阵 | 补充追溯关联后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式测试执行 | 全部【L2必填】章节（执行计划/进度跟踪/日报/总结报告） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 执行记录四要素、阻塞项分级与责任人、资金类阻断机制、退出指标三达标、四向追溯 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的资金类失败阻断决策与退出指标达标判定须由 QA 负责人确认；Agent 起草，QA 负责人确认后定稿。降级须经 PM + 合规审批并记录原因。
