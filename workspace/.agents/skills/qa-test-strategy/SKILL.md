# qa-test-strategy 技能

## 概述

本技能用于定义测试的整体策略：层级、范围、环境、数据与退出标准。

## 工作流

1. 读取需求与设计
2. 确定测试层级（单测/集成/SIT/UAT/性能/安全）
3. 明确测试环境与数据策略
4. 明确自动化范围
5. 定义可量化退出标准（执行率/通过率/遗留缺陷）
6. 输出测试策略文档


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 测试策略思路探索、层级范围讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，测试启动前策略定稿与退出标准制定 | 测试评审会 + QA负责人签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/高风险变更 | ARB/合规评审 + 深度门禁全通过 |

**自动升 L3 场景**：涉及反洗钱、限额参数、客户资金、监管报送、跨行接口、生产数据变更、核心账务系统首次上线时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- 输出分层测试策略+环境数据策略+可量化退出标准，层级间边界与入口/出口条件清晰
- 自动化范围与回归策略明确，标注P0用例自动化率目标（≥70%）与回归基线版本
- 退出标准含三大量化指标：用例执行率100%、通过率≥98%、遗留缺陷分级（致命/严重缺陷0、一般缺陷有处置计划）
- 环境数据策略含脱敏规则、数据量级（按生产1:1或1:10折算）、数据准备脚本与数据重置机制
- 资金/监管类需求须含专项测试策略（幂等性、冲正、限额边界、报送时效）
- 风险评估含测试缺口清单与残留风险说明，明确风险责任人

### L3 质量门禁

- [ ] 测试层级完整（单测/集成/SIT/UAT/性能/安全六层不缺）
- [ ] 退出标准三大量化指标齐全（执行率/通过率/遗留缺陷分级）
- [ ] 环境数据策略含脱敏规则与数据量级折算
- [ ] 自动化范围含P0用例自动化率目标与回归基线版本
- [ ] 资金/监管类需求有专项测试策略（幂等/冲正/限额/报送时效）
- [ ] 风险评估含测试缺口清单与残留风险责任人

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 退出标准模糊 | 用"基本通过/大致完成"等表述，无量化指标 | 强制三大量化指标模板（执行率/通过率/遗留缺陷分级） | 改写为量化表述后重审 |
| 测试层级遗漏 | 缺少安全测试或性能测试层级 | 六层完整性checklist + 风险驱动补充 | 补充缺失层级策略后重审 |
| 范围遗漏 | 需求未全覆盖到测试范围 | 需求覆盖清单 + RTM双向追溯 | 补充未覆盖需求后重审 |
| 环境数据策略缺失 | 未定义脱敏规则与数据量级 | 环境数据策略模板强制字段 | 补充脱敏与量级折算后重审 |
| 自动化范围不清 | 未标注P0自动化率目标与回归基线 | 自动化策略章节强制P0目标与基线版本 | 补充自动化目标后重审 |
| 资金/监管专项缺失 | 资金类需求未含幂等/冲正/限额测试策略 | L3自动升级触发 + 专项测试策略必填 | 补充专项策略后重审 |
| 风险评估无责任人 | 残留风险未指派责任人与处置计划 | 风险登记册模板强制责任人字段 | 补充责任人后重审 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式测试启动评审 | 全部【L2必填】章节（层级/范围/环境数据/退出标准/自动化范围） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统集成/首次上线 | 专项测试策略（幂等/冲正/限额/报送时效）、量化退出标准三指标、风险评估与缺口清单 | 风险降级或场景简化，经合规确认可回 L2 |

**人工兜底点**：L3 的退出标准量化指标与风险评估缺口清单须由 QA 负责人与 PM 共同确认；Agent 起草，QA 负责人确认后定稿。降级须经 PM + 合规审批并记录原因。
