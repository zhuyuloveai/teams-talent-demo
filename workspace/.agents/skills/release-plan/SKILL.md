# release-plan 技能

## 概述

本技能用于产出可执行、可回滚、可验证的发布计划。

## 工作流

1. 确认变更包与制品指纹（build_verify.py）
2. 编写发布顺序与窗口
3. 定义灰度策略与指标
4. 生成投产检查单
5. 干系人与通知确认


## 档位切换规则

| 档位 | 触发条件 | 审批要求 |
|------|---------|---------|
| L1 草稿 | 发布计划思路对齐、灰度策略讨论、Demo 走查 | 无需评审 |
| L2 标准（默认） | 银行生产默认档，G5安全放行通过后的发布准备 | 发布负责人 + CAB签字 |
| L3 实施级 | 涉及资金安全/监管报送/跨系统集成/首次上线/重大变更 | ARB/CAB评审 + 深度门禁全通过 |

**自动升 L3 场景**：发布涉及反洗钱、限额参数、客户资金、跨行接口、生产数据变更、首次上线、监管报送窗口、重大架构变更时，自动从 L2 升 L3；L3 须通过下方「深度档位（L3 实施级）」章节的全部可计算门禁。


## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3发布计划含命令级步骤+灰度阈值+回退触发条件
- 检查单逐项证据化
- 灰度策略须含分批比例（如1%→10%→50%→100%）、每批观察时长（≥30分钟）、通过指标阈值与回退触发条件（错误率/TPS/P95）
- 回退触发条件量化：错误率>0.1%、P95>基线1.5倍、TPS<基线80%、关键业务告警任一命中即回退
- 容量评估须含峰值TPS预估、资源水位（CPU<70%/内存<80%/磁盘<75%）、依赖系统容量确认
- 发布窗口冲突检测：与冻结期/监管报送窗口/其他发布任务无冲突，冲突时自动让位监管报送
- 监控指标清单含业务指标（交易成功率/金额核对）与技术指标（TPS/P95/错误率/资源水位），每项含告警阈值与责任人
- 投产检查单逐项证据化（命令输出/截图/日志链接），无证据项视为未完成

### L3 质量门禁

- [ ] 回退触发条件量化（错误率/TPS/P95/告警任一命中即回退）
- [ ] 灰度分批比例与每批观察时长明确（≥30分钟）
- [ ] 容量评估含峰值TPS与资源水位阈值
- [ ] 发布窗口无冲突（冻结期/监管报送/其他发布）
- [ ] 监控指标清单含业务+技术指标及告警阈值
- [ ] 投产检查单逐项有证据（命令输出/截图/日志链接）
- [ ] build_verify.py 退出码 0（制品指纹与构建记录一致）

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|------|---------|---------|
| 检查单流于形式 | 检查项无证据，仅打勾 | 强制证据项（命令输出/截图/日志链接） | 补齐证据后重审 |
| 回滚缺失 | 无回滚步骤或步骤不可执行 | 模板必填校验+命令级回滚 | 补齐命令级回滚后重审 |
| 灰度阈值模糊 | 仅写"观察异常则回退"，无量化指标 | L3要求量化阈值（错误率/TPS/P95） | 补齐量化阈值后重审 |
| 窗口冲突 | 与冻结期或监管报送窗口重叠 | 发布窗口冲突检测脚本+让位规则 | 调整窗口后重审 |
| 容量评估缺失 | 未评估峰值TPS与资源水位 | L3要求容量评估含峰值与水位阈值 | 补齐容量评估后重审 |
| 监控指标不全 | 仅技术指标无业务指标 | 业务+技术指标清单+告警阈值 | 补齐业务指标后重审 |
| 制品指纹不符 | 制品与构建记录sha256不一致 | build_verify.py校验退出码0 | 重新构建并校验指纹后重试 |

## 升级路径

| 升级方向 | 触发条件 | 增量字段 | 回退条件 |
|---------|---------|---------|---------|
| L1 → L2 | 进入正式发布准备 | 全部【L2必填】章节（变更包/发布顺序/灰度策略/检查单/回滚） | 评审退回，降为草稿 |
| L2 → L3 | 资金安全/监管报送/跨系统/首次上线 | 量化回退阈值+灰度分批+容量评估+窗口冲突检测+监控指标清单+证据化检查单 | 风险降级或变更简化，经CAB确认可回 L2 |

**人工兜底点**：L3 的回退触发条件与容量评估须由发布负责人与运维共同确认；Agent 起草发布计划，发布负责人确认后定稿。降级须经 CAB + ARB 审批并记录原因。
