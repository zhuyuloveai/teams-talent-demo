## 3. Code sets

**Campaign type `CampaignType`**: `FIRST_PURCHASE_CASHBACK` fixed cashback on the first purchase · `CATEGORY_CASHBACK` category rate / fixed cashback · `POINTS_MULTIPLIER` points multiplier

**Campaign status `CampaignStatus`**: `DRAFT` → `ACTIVE` ⇄ `PAUSED` → `ENDED` (final); rules can only be edited in `DRAFT`

**Reward status `RewardStatus`**: `PENDING` awaiting posting (can be retried through `fulfill`) · `GRANTED` issued · `FAILED` failed

**Eligibility reason codes** (`EligibilityPolicy`, in evaluation order):

| Reason code | Meaning |
|---|---|
| `CAMPAIGN_NOT_ACTIVE` | Campaign not in effect or outside its period |
| `ACCOUNT_NOT_FOUND` / `ACCOUNT_INACTIVE` | Account does not exist / account status is not `Y` |
| `ACCOUNT_GROUP_MISMATCH` | Account group does not match |
| `CATEGORY_MISMATCH` / `AMOUNT_TOO_LOW` | Transaction category does not match / below the minimum amount |
| `NOT_ENROLLED` | Enrollment required but not enrolled |
| `CARD_LIMIT_REACHED` / `FIRST_PURCHASE_ALREADY_REWARDED` | Per-card limit reached / first purchase already rewarded |
| `REWARD_ZERO` / `BUDGET_EXHAUSTED` | Reward is 0 / budget insufficient |
| `ALREADY_EVALUATED` | The same transaction has already been evaluated for the same campaign (`RewardEvaluationService`) |

None of the existing reason codes means "card tier does not match".

## 4. Identifier and amount rules

| Identifier / amount | Rule |
|---|---|
| Transaction ID | 16-character string |
| Card number | 16-digit string; the evaluation entry validates `\d{16}` |
| Account ID | 11-digit string; the evaluation entry validates `\d{11}` |
| Campaign ID / reward ID | 36-character UUID |
| Amount | `BigDecimal` / `NUMERIC(12,2)`, in yuan, never `double` |
