## 1. Core terms

| Term | Definition | Code mapping (carddemo-java-1025) |
|---|---|---|
| Platinum Card | The card tier that qualifies for this extra cashback | None (card tier field not yet implemented) |
| Standard Card | Any card other than a platinum card; does not qualify for this extra cashback | None |
| Extra Cashback | Additional cashback earned on platinum card spending within the period, at 0.5% (1/200) | `RewardComputation.cashback()` |
| Campaign Window | The time span in which cashback applies; the start instant is included, the end instant is not | `Campaign.startAt` / `endAt` |
| Integer Cents | Unit of amount calculation; rewards are calculated in cents first, rounding half a cent up to a whole cent | None (code calculates in yuan with `BigDecimal`) |
| Purchase | A posted purchase transaction; posting triggers reward evaluation | `PostingCommand` / `TransactionRecord` |
| Reward Evaluation | Deciding eligibility and calculating the reward after a purchase is posted | `RewardEvaluationService.evaluate()` |
| Reward Grant | The reward result of one campaign for one transaction, including its status | `RewardGrant` / `reward_grant` |
| Cashback Credit | Applying the cashback amount to reduce the account's outstanding balance | `Account.applyCashback()` / `reward_credit` |
| Current Balance | The account's used credit; purchases increase it, cashback reduces it | `Account.currentBalance` |
| Idempotency Key | The identifier that recognizes the same operation when it is processed again | `(campaign_id, transaction_id)`, `reward_id` |
| Pending | The retryable status kept after a cashback posting fails | `RewardStatus.PENDING` |
| Manual Retry | Starting the cashback posting again for a pending reward, reusing the same reward ID | `POST /api/v1/rewards/{rewardId}/fulfill` |
| Marketing Switch | When turned off, posting no longer calls reward evaluation; used for rollback | `marketing.enabled` |
| Access Token | HMAC-signed token issued by iam-service, containing the user ID, user type and expiry time | `HmacTokenService` |
| User Type | `A` admin / anything else is a regular user; only decides which menu opens after login | `User.landingMenu()` |

## 2. Easily confused concepts

| Term / field | Common misreading | Correct meaning |
|---|---|---|
| Platinum card customer | Same as the account group `groupId` | The documents define it by card tier; the existing `EligibilityPolicy` only checks the account group, and the mapping between the two is undefined |
| End instant of the spending period | Spending on 2027-02-01 00:00:00 still earns cashback that day | The end instant is **not included**; spending at or after that instant earns no cashback |
| Instant used for the period check | Decided by when the purchase happened | The documents define it by purchase time; the code decides by the system time at evaluation, so the two can differ at the period boundary |
| 0.5% cashback | Calculated in yuan, then rounded half up | Calculated in **integer cents**: extra cashback = purchase amount × 1/200, rounding half a cent up to a whole cent |
| Cashback and current balance | Cashback increases the account balance | `currentBalance` is the amount owed; cashback **reduces** it. After a CNY 120.00 purchase the balance goes from CNY 2550.75 to CNY 2670.15 |
| Repeated evaluation and repeated posting | Deduplicating once is enough | Two layers of idempotency: evaluation deduplicates by `(campaign_id, transaction_id)`, cashback posting deduplicates by `reward_id`; a retry must hit both layers |
| Evaluation failure and posting result | A failed reward evaluation rolls back the transaction | Marketing is an add-on benefit; a failed evaluation only raises an alert and the transaction is posted as usual |
| Carrying a token vs. being authenticated | A request that carries a token has passed validation | Resource services **do not validate** tokens in this phase; only iam-service's verify endpoint does. A gateway must be added before production |
